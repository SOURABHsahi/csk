1. Executive Architectural Overview

Knome is an enterprise-grade Knowledge Management & Hybrid Social Collaboration Platform engineered for MPOnline Limited. The backend application Backend/Knome.API is built on Microsoft ASP.NET Core 10.0, delivering ultra-fast response times, scalable RESTful APIs, real-time SignalR push notifications, and strict enterprise security controls.

Core Architecture Layers

  • Presentation Layer: Thin REST Controllers (Controllers/) returning standard ApiResponse<T> envelopes.
  • Service Layer: Encapsulated Business Logic (Services/) enforcing validation, permissions, and moderation workflows.
  • Data Access Layer: Generic Repository Pattern (Repositories/) over EF Core 10 KnomeDbContext.

Key Non-Functional Requirements

  • Security: JWT HS256 authentication, BCrypt work factor 11 password hashing, role-based authorization (RBAC), and Suspension Guard middleware.
  • Performance: Compiled EF Core queries, async/await I/O, SignalR Websockets, and background worker expiration.
  • Data Integrity: Centralized transaction management and FluentValidation pipeline filters.

3. Application Startup & Pipeline Architecture

The backend initialization workflow resides in Program.cs, Extensions/ServiceCollectionExtensions.cs, and Extensions/ApplicationBuilderExtensions.cs.

3.1 Dependency Injection Assembly (AddInfrastructure)

All framework services, authentication schemes, Swagger OpenAPI documentation, and application components are registered via AddInfrastructure(IServiceCollection, IConfiguration): 

public static IServiceCollection AddInfrastructure(this IServiceCollection services, IConfiguration configuration)
{
    // 1. Database Wiring (EF Core SQL Server)
    services.AddDbContext<KnomeDbContext>(options =>
        options.UseSqlServer(configuration.GetConnectionString("DefaultConnection")));

    // 2. Authentication & Authorization (JWT HS256)
    services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
        .AddJwtBearer(options => { ... });

    // 3. Application Services & Repositories Registration
    services.AddScoped(typeof(IRepository<>), typeof(Repository<>));
    services.AddScoped<IUserRepository, UserRepository>();
    services.AddScoped<IUserService, UserService>();
    // ... registers all 16 Services & 14 Repositories

    // 4. SignalR & Background Hosted Worker
    services.AddSignalR();
    services.AddHostedService<JobExpiryHostedService>();

    return services;
}

3.2 Middleware Execution Pipeline (UseInfrastructure)

The request pipeline sequence is strictly ordered in ApplicationBuilderExtensions.cs to guarantee security and exception safety:

  1. ExceptionHandlingMiddleware: Catches all unhandled exceptions globally and formats a unified JSON response envelope.
  2. SecurityHeadersMiddleware: Injects HTTP security headers (CSP, X-Frame-Options, X-Content-Type-Options, HSTS).
  3. UseCors("AllowFrontend"): Permits cross-origin requests from the React frontend server.
  4. UseAuthentication() & UseAuthorization(): Evaluates JWT claims and user identity.
  5. SuspensionGuard: Verifies if the authenticated user account has been suspended by System Admin.
  6. MapControllers() & MapHub<NotificationHub>("/hubs/notifications"): Endpoints execution.

5. Core Business Modules & Logic Architecture

Source-of-Truth Architecture: All business logic is encapsulated inside single-responsibility Service classes located in Services/. Repositories in Repositories/ deal exclusively with EF Core query generation and SQL execution.

5.1 Media Approval & Admin Moderation Workflow

To ensure enterprise compliance and content safety, a multi-tier moderation workflow is enforced across media uploads (Videos and Podcasts):

  1. Role Check: When a user calls /api/Videos or /api/Podcasts, VideoService / PodcastService evaluates user role.
  2. Admin Direct Upload: If the uploader possesses an Admin role (System Administrator, HR Administrator, Community Administrator), the content is immediately saved as Approved and published.
  3. Employee Queueing: If uploaded by a standard Employee, the media is saved with status PendingApproval. An automated notification alert is generated for System Administrators.
  4. Admin Review: Admins access the Media Approvals Queue in AdminConsole to preview audio/video metadata and click Approve or Reject.
  5. Publication & Notification: Approving the item publishes it to public feeds and sends a real-time SignalR notification to the author.

5.2 Hot Posts Ranking & Time-Decay Engine (FeedService.cs)

The platform computes trending content dynamically using an engagement gravity formula: 

HotScore = (Reactions * 1.0 + Comments * 2.0 + Shares * 3.0 + Bookmarks * 2.5) / Math.Pow(AgeHours + 2, 1.5)

This ensures recent high-engagement posts rank highest on the Dashboard while older posts naturally decay over time.

5.3 Gamification & Karma Points Engine (KarmaService.cs)

Employee engagement is incentivized via automated Karma point allocations:

  • Post Creation: +2 Karma Points (Max 10 pts/day)
  • Article Publication: +10 Karma Points (Max 30 pts/day)
  • Video Upload: +8 Karma Points
  • Comment Added: +2 Karma Points
  • Reaction Received: +1 Karma Point
