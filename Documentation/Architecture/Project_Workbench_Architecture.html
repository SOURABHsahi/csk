1. Introduction & Executive Context

This document describes the High-Level Architecture (HLA) of the Project Workbench (PWB) — a centralized Project Governance, Monitoring, and Delivery Management platform for MPOnline Limited, integrating seamlessly with MPOEmployeeHub for enterprise identity and Single Sign-On (SSO).

1.1 Business Context & Strategic Objectives

PWB serves as the single source of truth for executive project oversight, delivering a 360-degree view across:

Functional Governance Scope Area Functional Governance Scope Area
• Government Department Projects • Financial & Operational KPIs
• Citizen Service Initiatives • Milestones & Planning
• e-Governance Programs • Alerts & Notifications
• UPP Network & District Performance • Reporting, Analytics & Power BI
• Vendor & Partner Management • Project Governance & Audit
• Risk & Compliance Monitoring • Executive Dashboards & SLA Oversight

1.2 Architecture Scope & Summary

PWB follows a six-layer architecture where React provides the user interface, Next.js provides the browser-facing BFF, YARP acts as the common gateway, MPOEmployeeHub provides SSO and identity, .NET APIs provide PWB business functionality, and MSSQL provides persistence.

Layer Layer Name Technology Primary Architectural Responsibility
1 React Frontend UI React UI (Vite / SPA) Browser-facing user interface where users interact with PWB.
2 Next.js BFF Next.js Backend For Frontend — manages session boundary & HttpOnly cookie.
3 YARP Gateway (.NET) .NET / YARP Common security & traffic gateway — routing, rate limiting, auth check.
4 MPOEmployeeHub SSO Identity Platform User authentication, Single Sign-On, JWT token issuance & lifecycle.
5 PWB Backend APIs .NET / ASP.NET Core All PWB business logic — Departments, Projects, Milestones, Risk, Finance.
6 MSSQL Server Microsoft SQL Server Persistent data storage — business records, transactions, audit logs.

Workflow Phase Source & Destination Architectural Action & Security Boundary Enforcement
1. Login Initiation React UI ➔ Next.js BFF ➔ YARP User provides credentials. BFF dispatches auth request via YARP edge gateway without exposing tokens to browser JS.
2. Identity Validation YARP ➔ MPOEmployeeHub ➔ DB MPOEmployeeHub validates employee credentials, evaluates roles (HR Admin, Project Mgr, Employee), and signs JWT tokens.
3. Session Setup EmployeeHub ➔ YARP ➔ BFF ➔ UI BFF encapsulates JWT in an encrypted HttpOnly, SameSite=Strict cookie, shielding tokens from client scripts.
4. API Execution UI ➔ BFF ➔ YARP ➔ .NET APIs BFF hydrates Bearer header from cookie. YARP validates signature and claims. .NET APIs execute domain business rules.
5. Data Persistence .NET APIs ➔ MSSQL Server Entity Framework Core queries and updates transactional project schemas, milestones, risks, and financial records.
6. Session Termination UI ➔ BFF ➔ YARP ➔ EmployeeHub EmployeeHub revokes active token session. BFF clears browser cookie (Max-Age=0), ensuring complete session invalidation.

2.1 Core Security & Communication Protocol Rules

  • Zero-Trust Browser Boundary: Access tokens and refresh tokens are never delivered to or stored inside the browser's localStorage or sessionStorage.
  • Strict Reverse Proxy Ingress: Direct ingress to Layer 4 (EmployeeHub) and Layer 5 (Backend APIs) is forbidden. All external network ingress routes through Layer 3 (YARP Gateway).
  • End-to-End TLS Encryption: All transport channels across edge and internal microservices enforce HTTPS/TLS 1.3 encryption.

3. Login & Authentication Workflow

MPOEmployeeHub is the sole owner of authentication and identity. The user's login request reaches MPOEmployeeHub through the common YARP Gateway, which returns the callback through YARP to establish the BFF secure HttpOnly cookie session.

4
BFF forwards auth request to YARP Gateway: BFF passes request to common gateway
▼
5
YARP routes auth request to MPOEmployeeHub: YARP proxies to identity provider
▼
6
MPOEmployeeHub authenticates user: Validates credentials against identity store
▼
7
MPOEmployeeHub creates & returns JWT token: Issues signed authorization JWT token
▼
8
MPOEmployeeHub redirects/callbacks via YARP: Sends auth callback through YARP
▼
9
YARP routes callback back to BFF flow: Proxies callback result to Next.js BFF
▼
10
BFF processes authentication result: BFF handles token & session setup
▼
11
Secure HttpOnly cookie session established: Stores session token in HttpOnly cookie
▼
12
User reaches authenticated PWB app: React renders authenticated portal dashboard
[KEY ARCHITECTURE PRINCIPLES — LOGIN]
• The browser never directly authenticates against MPOEmployeeHub without passing through the defined architecture.
• YARP is the common gateway through which all authentication traffic passes.
• The JWT / token lifecycle is owned by MPOEmployeeHub — not by the browser or React UI.
• The BFF establishes a secure HttpOnly cookie to maintain the browser session.

5. Logout & Session Invalidation Workflow

Logout is not simply hiding the UI. Authentication and session validity are invalidated at the identity layer (MPOEmployeeHub). Once invalidated, the user's previous session cannot be used to resume protected operations.

1
User clicks Logout in React UI: User initiates sign-out action in portal settings
▼
2
React sends logout request to Next.js BFF: UI calls BFF logout endpoint
▼
3
BFF sends logout request through YARP: BFF proxies logout call to gateway
▼
4
YARP routes logout request to MPOEmployeeHub: YARP routes logout to identity platform
▼
5
MPOEmployeeHub invalidates session & JWT token: Identity provider invalidates active session/token
▼
6
Logout callback sent back through YARP to BFF: SSO confirms session termination
▼
7
BFF clears / expires browser HttpOnly cookie: Destroys browser-facing secure session cookie
▼
8
Protected access is no longer valid: All subsequent API calls rejected with 401 Unauthorized
▼
9
User is redirected back to Login page: React navigates user to login entry screen
▼
10
Login lifecycle must start again for access: User must authenticate from Step 1 for new session
[SECURITY STATEMENT — LOGOUT INVALIDATION]
After logout, the user's previous authenticated session / token cannot be used to continue protected PWB operations. Protected access is invalidated at MPOEmployeeHub and BFF cookie level, forcing a complete new login lifecycle for subsequent access.

6.3 Architecture Principles & Rules

Rule # Mandatory Architectural Principle Statement
1 React is presentation / UI only — no direct database calls or business logic.
2 Next.js BFF is the browser-facing session boundary — manages HttpOnly cookies and session storage.
3 YARP is the common security gateway through which all protected PWB traffic passes.
4 MPOEmployeeHub owns authentication, SSO, and identity token lifecycle end-to-end.
5 Layer 5 owns all PWB business functionality — APIs, business rules, and integrations.
6 Layer 6 owns persistent data storage — business data, transactions, and audit records.
7 All service-to-service communication must enforce HTTPS encryption.
8 Role-based authorization must be validated before protected business operations execute.
9 Backend complexity must be hidden from the browser client via the BFF layer.
10 Exact low-level class designs, DB schemas, and API JSON payloads belong to LLD.
