Enterprise Architecture Overview Slide 2
lock_open Single Sign-On (SSO)

EmployeeHub & Knome Shared JWT Architecture

Seamless zero-click authentication between EmployeeHub Identity Server and Knome Portal.

[1. EmployeeHub Login (:5001)] Employee inputs credentials -> Validates against identity DB. Issues HMAC-SHA256 Signed JWT (Claims: sub, employeeId, role). │ ▼ [2. Seamless SSO Redirect] Redirects to: http://localhost:5173/?sso_token={JWT}&employeeId={MPO103} │ ▼ [3. Knome Frontend Token Catch] UserContext stores token in localStorage, sanitizes URL bar. │ ▼ [4. Knome API Dual-Issuer Validation (:5095)] TokenValidationParameters trusts: ["Knome.API", "EmployeeHub.Identity"] Validates Signature with shared SecretKey -> User Logged In!

Dual-Issuer Trust

Both systems share cryptographic verification keys so no extra round-trip or redundant token exchange is required.

URL Query Sanitization

Immediately on load, window.history.replaceState purges token query params from the browser address bar for security.

Multi-Role Claim Synchronization

Employee, Community Admin, HR Admin, or SysAdmin roles are extracted directly from token claims.
